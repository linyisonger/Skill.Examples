## 一、如何触发（Trigger）

### 1.1 标准触发词

用户说出以下任意意图时，Agent 应调用本框架：

| 类别 | 触发词示例 |
|------|-----------|
| 大盘分析 | "今日行情分析"、"收盘点评"、"大盘怎么看"、"今天市场总结" |
| 个股/ETF 分析 | "512660 技术面怎么样"、"510300 能买吗"、"军工 ETF 走势" |
| 板块分析 | "半导体板块今天如何"、"哪个板块强"、"板块轮动怎么看" |
| 操作建议 | "今天如何操作"、"现在能加仓吗"、"要不要清仓" |
| 对比分析 | "科技 ETF 和 军工 ETF 哪个强"、"宽基里谁更值得持有" |

### 1.2 调用流程

Agent 收到触发后，按以下顺序执行：

```
1. 识别标的 → 用户指定？用用户的；未指定？用第四节默认 ETF 清单
2. 获取数据 → 按第二节搜索数据；**大盘速览类分析严格按 2.6 一次性并行取数，禁止分批与冗余补取**
3. 校验数据 → 按第三节检查完整性、一致性、时效性
4. 套用框架 → 按第五节七维度逐条分析
5. 输出信号 → 按第六节操作术语给出信号 + 置信度
6. 风险提示 → 文末统一声明：纯技术面，不构成投资建议
```

### 1.3 默认输出格式

每次分析必须包含：

- **标的与数据源**：代码、名称、数据时间、来源
- **七维度摘要**：趋势、量价、均线、指标、支撑阻力、板块轮动、变盘信号
- **操作信号**：买入/持有/减仓/卖出/观望/轻仓试多/做T（七选一）
- **置信度**：高 / 中 / 低
- **关键价位**：支撑位、压力位（如数据允许）
- **风险提示**：纯技术面，不构成投资建议

## 二、数据源与获取规范

### 2.1 数据源优先级

**优先级 1：westock-mcp（已连接，优先使用）**

当 westock-mcp 可用时，优先通过 MCP 工具获取结构化行情数据，避免 WebSearch 的口径不一致和广告干扰。

**优先级 2：WebSearch（备用 / 交叉校验）**

当 MCP 不可用、返回异常、或需要补充市场解读时，再用 WebSearch 从主流财经网站获取。

### 2.2 westock-mcp 工具映射

| 数据需求 | 首选工具 | 关键参数 |
|----------|----------|----------|
| 代码搜索/确认 | `mcp__westock-mcp__data_search` | `query=关键词`, `type=stock,etf,index,sector` |
| 实时行情快照 | `mcp__westock-mcp__data_quote` | `code=sh600519` 或 `codes=sh510050,sz159949` |
| K 线/均线/趋势 | `mcp__westock-mcp__data_kline` | `code=sh510300`, `period=day`, `limit=250`, `fq=qfq` |
| 技术指标 | `mcp__westock-mcp__data_technical` | `code=sh510300`, `group=kdj,macd` |
| ETF 详情 | `mcp__westock-mcp__data_etf` | `code=sh512660`, `aspect=overview` |
| 指数行情/成份 | `mcp__westock-mcp__data_index` | `code=sh000300`, `mode=constituent` |
| 板块资金排名 | `mcp__westock-mcp__data_sector` | `mode=ranking`, `type=mainNetInflow`, `kind=industry` |

### 2.3 调用示例

**获取 510300 沪深300ETF 实时快照 + 日 K 线 + 技术指标：**

```
mcp__westock-mcp__data_quote:  {"code":"sh510300"}
mcp__westock-mcp__data_kline:  {"code":"sh510300","period":"day","limit":120,"fq":"qfq"}
mcp__westock-mcp__data_technical: {"code":"sh510300","group":"kdj,macd"}
```

**获取行业板块资金流向排名：**

```
mcp__westock-mcp__data_sector: {"mode":"ranking","type":"mainNetInflow","kind":"industry","limit":20}
```

### 2.4 WebSearch 备用查询（MCP 失败时使用）

- 指数：`"上证指数 今日 收盘 涨跌幅 成交额"`、`"创业板指 今日 行情"`
- ETF：`"510050 上证50ETF 今日 收盘价 成交量"`、`"512660 军工ETF 最新 净值 资金流"`
- 板块：`"今日 A股 行业板块 涨幅榜 资金流向"`、`"半导体板块 今日 主力资金"`

### 2.5 优先字段（必备字段）

每个标的分析前必须获取：

| 字段 | 说明 | 缺失处理 |
|------|------|----------|
| 收盘价 | 最新收盘价或实时价 | 缺失则该标的降权 |
| 涨跌幅 | 当日涨跌幅 | 缺失则该标的降权 |
| 成交量/额 | 当日成交量或成交额 | 缺失则量价维度降权 |
| 均线位置 | 5/20/60/120/250 日均线至少前 3 条 | 缺失则均线维度降权 |
| MACD/KDJ | 至少一个指标状态 | 缺失则指标维度降权 |

### 2.6 大盘速览标准取数（一次性并行，提速度）

做「今日盘面 / 收盘点评」类大盘分析时，按以下**单批并行**清单取数，避免分批往返与冗余补取。实测可将取数耗时从 ~4m37s 压缩到 <1 分钟。

| 次序 | 工具 | 参数 | 用途 |
|------|------|------|------|
| 1 | `mcp__westock-mcp__data_market_overview` | `{"type":"all"}` | 大盘涨跌分布/技术评分/估值/风格轮动（**以返回 `date` 字段为准**；盘后早段可能仍是上一交易日快照，约 19:00 后自动刷新为当日，见 3.3） |
| 2 | `mcp__westock-mcp__data_sector` | `{"mode":"ranking","type":"changePct","kind":"industry","order":"desc","limit":20}` | 当日行业涨跌榜 |
| 3 | `mcp__westock-mcp__data_quote` | `{"codes":"sh000001,sz399001,sz399006,sh510300,sh588000,sh512070,sh512800,sh512660"}` | 三大指数 + 5 只核心 ETF 实时快照（一次取 8 只） |
| 4 | `mcp__westock-mcp__data_technical` | `{"codes":"sh510300,sh588000,sh512070,sh512800,sh512660","group":"kdj,macd"}` | 5 只 ETF 的 MACD/KDJ |

**提速要点（务必遵守）**：

- 以上 4 个调用**放在同一条消息里并行发出**，不要分批改。
- **以 `data_market_overview` 返回的 `date` 字段为准标注实际交易日**：盘后不久可能仍吐上一交易日聚合（约 19:00 前常为 T-1），之后自动刷新为当日；不要反复传 `date=当日` 重试，按实际返回日期标注时效即可。
- **不要**单独拉 ETF 原始 `data_kline`：ETF 均线非必需（大盘均线取自 overview 聚合），MACD/KDJ 已由 `data_technical` 覆盖；确需 ETF 均线时再单独补 1 只。
- 核心 ETF 固定 5 只（510300/588000/512070/512800/512660），不要默认拉满第四节 15 只清单。

## 三、数据校验与异常处理

### 3.1 数据完整性校验

分析前检查必备字段是否齐全：

- **全部缺失**：输出 `[数据缺失：当前标的无法获取有效行情，跳过分析]`，并建议用户检查代码或稍后重试。
- **部分缺失**：输出 `[数据缺失：X 项，结论降权]`，缺失维度不参与强判断，最终信号置信度不得高于"中"。

### 3.2 来源冲突处理

同一字段多个来源不一致时：

1. 优先采用主流行情终端口径（如东方财富、同花顺、新浪财经）。
2. 若仍冲突，取最新发布的数据源。
3. 输出中显式标注：`[口径冲突：A源显示 X，B源显示 Y，本次取 Y 并说明原因]`。

### 3.3 时效性校验

- 记录数据对应的交易日与时段。
- 盘前/午间搜索到的上一交易日收盘数据，必须标注：`[数据非实时：当前为上一交易日收盘数据]`。
- 盘后数据标注：`[数据已收盘：日期 YYYY-MM-DD]`。

### 3.4 MCP 失败与降级处理

- **MCP 调用失败（超时/报错/无返回）**：记录失败原因，自动降级到 WebSearch；输出中标注 `[MCP 不可用，已降级为 WebSearch 数据]`。
- **MCP 返回字段不完整**：缺失字段用 WebSearch 补充；补充失败则按「部分缺失」降权。
- **MCP 与 WebSearch 口径冲突**：优先采用 MCP 数据，但标注 `[MCP: X，WebSearch: Y，本次取 MCP 口径]`。
- **搜索无结果**：输出 `[搜索无结果：当前数据源不可用]`，提示用户稍后重试或手动提供数据。
- **返回结果混乱/广告过多**：尝试更换关键词重搜一次；若仍失败，输出 `[数据质量不足：结论降权]`。

### 3.5 低置信度处理

当信号置信度为"低"时，必须：

1. 在信号后追加：`[低置信度：仅作参考，需等待确认，不建议据此操作]`。
2. 说明低置信度原因（如"均线粘合方向不明"、"量能萎缩无方向"、"关键数据缺失"）。
3. 给出明确的确认条件（如"放量突破 X 元可提升置信度"、"跌破 Y 元则信号失效"）。

## 五、技术分析框架（七维度）

分析时遵循以下维度，输出纯技术判断，不带情绪化表述：

### 5.1 趋势结构
- 日线/30分钟级别走势类型（上涨/下跌/盘整）
- 中枢位置与边界（上沿/下沿）
- 高低点序列（是否下移/上移）

### 5.2 量价关系
- 成交量/成交额放量或缩量
- 地量/倍量信号
- 量价配合（放量上涨/缩量下跌/放量滞涨）

### 5.3 均线系统
- 5/20/60/120/250 日均线位置关系
- 均线方向（上行/下行/走平）
- 年线（250日）趋势对中长期方向的指引

### 5.4 技术指标
- MACD：金叉/死叉、柱体放大/缩小、背离
- KDJ：超买/超卖、收敛/发散

### 5.5 支撑阻力
- 关键整数关口
- 前期高/低点
- 均线支撑/压力位

### 5.6 板块轮动
- 资金高低切换信号
- 板块间强弱对比
- 底部构筑形态（W底/头肩底/中枢震荡）

### 5.7 变盘信号
- 波动率放大
- 连续上下引线宽幅震荡
- 地量后放量方向选择

## 六、操作术语体系

当用户询问「今日行情分析」「今天如何操作」「收盘前分析」等操作性问题时，必须在每个 ETF 分析后附带操作建议。操作术语统一使用以下体系，并**标注置信度（高/中/低）**：

| 操作信号 | 适用场景 | 技术依据 |
|----------|----------|----------|
| **买入/加仓** | 放量突破关键阻力、均线金叉、MACD 金叉、底部放量反转 | 趋势确认+量能配合 |
| **持有/持仓不动** | 趋势完好、量价健康、未触发止盈止损 | 趋势延续中 |
| **减仓/止盈** | 放量滞涨、高位放量长上影、KDJ 超买死叉 | 上涨动能衰竭 |
| **卖出/清仓** | 跌破关键支撑、放量破位、均线死叉、MACD 死叉 | 趋势逆转确认 |
| **观望/不参与** | 缩量盘整方向不明、技术位尴尬（不上不下）、波动率过低 | 无明确信号 |
| **轻仓试多** | 底部放量初现、超跌后首根放量阳线、但趋势未确认 | 左侧试探 |
| **做 T / 日内交易** | 震荡市中触及区间上沿/下沿、高抛低吸 | 中枢震荡边界 |

> 低置信度信号必须提示「仅作参考，需等待确认」，严禁诱导操作。

## 七、完整分析案例

### 案例：军工 ETF（512660）技术面分析

**输入**："512660 技术面怎么样？"

**执行步骤**：

1. **代码确认**：`mcp__westock-mcp__data_search` `{"query":"512660","type":"etf"}` → 确认代码为 `sh512660`。
2. **实时行情**：`mcp__westock-mcp__data_quote` `{"code":"sh512660"}` → 收盘价、涨跌幅、成交额。
3. **K 线与均线**：`mcp__westock-mcp__data_kline` `{"code":"sh512660","period":"day","limit":120,"fq":"qfq"}` → 计算 5/20/60/120/250 日均线。
4. **技术指标**：`mcp__westock-mcp__data_technical` `{"code":"sh512660","group":"kdj,macd"}` → KDJ、MACD 状态。
5. **板块资金**：`mcp__westock-mcp__data_sector` `{"mode":"ranking","type":"mainNetInflow","kind":"industry","limit":30}` → 军工板块排名。
6. **校验**：获取到收盘价、涨跌幅、成交额、均线、MACD/KDJ 状态。
7. **套用七维度**：

| 维度 | 分析内容 |
|------|----------|
| 趋势结构 | 日线处于中枢震荡，高点未创新高，低点逐步抬升 |
| 量价关系 | 今日缩量回调，成交额较前 5 日均值下降约 15% |
| 均线系统 | 股价位于 5 日、20 日均线上方，60 日均线走平 |
| 技术指标 | MACD 红柱缩短，尚未死叉；KDJ 高位收敛 |
| 支撑阻力 | 支撑位 1.05 元（20 日均线），压力位 1.12 元（前期高点） |
| 板块轮动 | 军工板块今日资金净流入排名中游，非主线 |
| 变盘信号 | 中枢收窄，等待放量选择方向 |

**输出信号**：

> **512660 军工ETF**：当前处于中枢震荡，趋势未明。MACD 红柱缩短 + KDJ 高位收敛，短期动能减弱；但股价仍在 20 日均线上方，尚未破位。
>
> **操作信号**：观望 / 持仓不动
> **置信度**：中
> **关键价位**：支撑 1.05，压力 1.12
> **确认条件**：放量突破 1.12 可转"持有/轻仓试多"；跌破 1.05 且放量则转"减仓"。
>
> **风险提示**：纯技术面分析，不构成投资建议。当前信号为"中"置信度，建议等待方向确认。

## 十、FAQ

### Q1：这个 Skill 能直接下单交易吗？
**不能。** 本 Skill 只输出技术分析观点与操作建议，不连接任何交易接口，也不执行买卖操作。

### Q2：为什么有时给出"观望"信号？
当技术信号不明确、数据缺失、或价格处于多空临界区时，"观望"是最安全的中性判断，避免在方向不明时强行诱导操作。

### Q3：默认 ETF 清单可以改吗？
可以。清单是「未指定标的时」的默认覆盖范围。用户给出具体代码或名称时，以用户指定为准。

### Q4：低置信度信号还要参考吗？
低置信度信号仅作学习参考，不建议据此实际操作。应等待信号确认条件满足后再提升置信度。

### Q5：数据来源是什么？
默认通过 WebSearch 从主流财经网站获取公开行情数据。若 westock-mcp 等行情工具已连接，优先使用其数据。

### Q6：没有实时数据怎么办？
Agent 会标注数据时效性（实时/收盘/上一交易日）。若完全无法获取数据，会输出 `[数据缺失]` 并建议稍后重试。

### Q7：分析结果可靠吗？
技术分析基于历史价格和成交量规律，不保证未来走势。每次输出均会附带置信度和风险提示，请结合自身风险承受能力判断。
